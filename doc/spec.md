# 構造化テーブルエディタ (Table Spec Editor) 仕様書

## 1. 概要
本拡張機能は、非エンジニア作業者が表形式の仕様書を直感的に入力し、Gitでクリーンに差分管理できるYAML形式および納品用Markdown形式を安全に生成・保守するためのVS Codeカスタムエディタである。

業務ドメインに依存しない汎用的なアーキテクチャを採用しており、プロジェクト内のスキーマ定義ファイル（`*.schema.yaml`）により、列定義、バリデーション、Markdownテンプレートを動的に切り替える。

---

## 2. アーキテクチャとデータフロー


```

[ .schema.yaml ] (スキーマ定義: 複数同居可)
│
▼
[ *.spec.yaml ] ◄───► [ Webview Custom Editor ]
│                      │
│ (Ctrl+S 保存時のみ)    │ (Excel双方向コピペ)
▼                      ▼
[ *.spec.md ]             [ MS Excel ]

```

1. **データ正本 (`*.spec.yaml`)**:
   すべてのデータはYAMLに格納する。複数行テキストはリテラルブロック（`|`）形式で保持され、Git PRレビュー時の行単位差分を保証する。
2. **成果物 (`*.spec.md`)**:
   VS Code上でファイル保存（`Ctrl+S`）が実行されたタイミングでのみ、スキーマに定義された `markdown_template` をもとに自動同期・出力される。
3. **スキーマ決定メカニズム**:
   データYAML内の `schema: <schema_id>` フィールドに基づき、対応するスキーマ定義を動的にバインドする。

---

## 3. 機能要件

### 3.1 エディタ機能
* **カスタムエディタ連携**: `*.spec.yaml` / `*.spec.yml` を開いた際、専用テーブルUIを初期起動する。
* **動的UI構築**: スキーマ定義に基づいてヘッダーフォーム、テーブル列ヘッダー、列幅、入力形式（1行/複数行/プルダウン）を動的に構成する。
* **自動行制御**:
  * テーブル末尾には常に新規入力用空行（`*`）を1行表示する。
  * 入力が行われると自動で正式行へ昇格し、次の空行を生成する。
  * 全セルが空の行はYAMLシリアライズ時に自動除外する。
* **後方互換性とデータ保全**:
  * スキーマ変更により画面上から列が削除・変更された場合でも、既存YAML内に存在する未定義フィールドを破棄せず保持して再保存する。
* **キー順の保持**:
  * YAMLシリアライズ時、キー順をアルファベット順にソートせず（`sortKeys: false`）、元の構造を維持してGitの不要な差分を防止する。

### 3.2 Excel連携・スプレッドシート操作
* **Excelゼロ落ち防止コピー**:
  * 矩形選択して `Ctrl+C` を実行した際、クリップボードに `text/plain`（TSV）と同時に `text/html`（`mso-number-format:'\@'`）を格納する。
  * Excel貼り付け時に `001` などの文字列が数値 `1` に型変換される現象を防止する。
* **Excel貼り付け**:
  * セル内改行を含むExcelの矩形データを `Ctrl+V` で正確に2次元展開する。行が不足している場合は自動拡張する。
* **IME入力保護**:
  * 日本語入力（全角入力・変換）のキー操作とテーブルショートカット（セル移動・確定）の衝突をガードする。
  * セル選択からの直接打鍵による1文字目消失を防ぐため、「ダブルクリックまたはEnterで明示的に編集モードに突入する」ステートマシンを採用する。

### 3.3 バリデーション機能
* **必須チェック**: `required: true` のカラムで空値を検証。
* **選択肢チェック**: `type: select` かつ `options_strict: true` の場合、リスト外の入力を検証。
* **正規表現パターン**: `pattern` に定義された正規表現への合致を検証。
* **視覚的フィードバック**: バリデーション違反セルは赤枠ハイライトおよび「!」マークを付与し、ホバーでエラーメッセージを表示する。

## 4. スキーマ定義ファイル仕様 (`*.schema.yaml`)

| フィールド | 型 | 必須 | 説明 |
| :--- | :--- | :---: | :--- |
| `schema_id` | string | ○ | スキーマの一意識別子（データ側の `schema` フィールドと一致） |
| `schema_version`| string | ○ | スキーマのバージョン |
| `title` | string | ○ | 仕様書の論理名 |
| `headers` | array | － | テーブル外の共通ヘッダー入力欄定義（画面IDなど） |
| `header_layout` | string | － | `vertical` でヘッダーを項目・値の2列表にする。未指定時は従来の横並び |
| `columns` | array | ○ | テーブルの列構造定義 |
| `scenario_heading` | object | － | 設定時、各メインテーブル行をシナリオとして自動見出しを付ける |
| `markdown_template`| string | ○ | Markdown出力用テンプレート |

### 4.1 列定義 (`columns`)
* `key`: データ上のキー名
* `label`: テーブルヘッダー表示名
* `width`: 初期列幅（px）
* `type`: `string` | `multiline` | `select`
* `options`: `type: select` 時の選択肢配列
* `options_strict`: 定義外の値をバリデーションエラーとするか否か
* `pattern`: 入力制限用正規表現
* `pattern_error`: パターン不一致時のエラーメッセージ
* `align`: Markdown出力時の配置（`left` | `center` | `right`）

### 4.2 ヘッダー・シナリオ定義

`header_layout: vertical` を指定すると、`headers` の各項目を「項目」「値」の2列表に縦方向に表示する。未指定時の横並び表示は変わらない。ヘッダー定義では `type: multiline` による複数行入力、`required`、`pattern`、`pattern_error` を指定できる。

`scenario_heading` とサブテーブル内の同名設定は、各行を1シナリオとして扱う。行の `_indent` から `シナリオ1`、`シナリオ2-1` のような見出し番号を自動生成し、Markdown の見出しレベルも階層に応じて下げる。メインフローは `items`、代替フローは別のサブテーブル配列に分け、各行の複数ステップは `multiline` 列に記述する。階層番号はそれぞれの配列内で独立して算出される。

ユースケース記述スキーマでは、アクター、条件、トリガーを独立したサブテーブルで管理する。アクターとトリガーは複数行で記述でき、条件表では各行に事前条件または事後条件を設定する。Markdown には各一覧を表形式で出力し、アクターはユースケース図にも出力する。

ユースケース名、概要、パッケージ、関連要求IDは「ユースケース基本情報」サブテーブルの項目・内容行で管理する。内容は複数行入力でき、関連要求IDは任意とする。テンプレート内の `{{basic_info:項目名}}` は、基本情報テーブルでその項目名に一致する最初の行の内容に置換する。

```yaml
scenario_heading:
  label: シナリオ
  markdown_level: 3
```

## 5. ビルドおよびパッケージング手順

### 5.1 依存ライブラリのインストール
```bash
npm install

```

### 5.2 TypeScriptコンパイル

```bash
npm run compile

```

### 5.3 パッケージング (`.vsix`)

```bash
npx vsce package

```

生成された `table-spec-editor-1.0.0.vsix` をVS Codeの「VSIX からのインストール」で導入する。
